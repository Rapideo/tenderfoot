## Global constraints

- **Foreign keys stay enforced.** Design spec §2.2 names retrofitting entity FKs as *the* expensive mistake. In Postgres this stops depending on a `PRAGMA` any second connection could silently lose — **strictly better, and the tests must still prove it.**
- **`value_cents` becomes `bigint`.** A contract above ~$21.4M overflows a 32-bit `integer`, and the corpus holds contracts in that range. **This is the one silent data-loss bug available in this port.**
- **Nothing is enabled.** `source.enabled` stays false for every row. SP3 turns the first one on deliberately, after the ingestion window exists in code.
- **No fact about Koehler Partners moves into code** (§2.1, §7.8). The firm profile stays a seeded row.
- **`npm run check` stays green** — typecheck, tests, build, token drift. It is the gate and it must not get slower than "a few seconds" without that being noticed (`Proto2PRD-Lessons.md` §3 watch item).

## Decisions taken in this plan

**1. `pg` (node-postgres), not `@neondatabase/serverless`.** Both work. `pg` is identical against Neon's pooled endpoint, a local Postgres, and a CI service container — **one driver, one code path, no environment where the client differs.** `@neondatabase/serverless` earns its place only when something runs on the edge runtime, and Express does not.

**2. Query helpers, not an ORM.** SP0 chose a hand-rolled migration runner over a library so it stayed readable in one sitting; the same reasoning applies. Four thin functions — `all`, `one`, `run`, `tx` — and raw SQL everywhere else. **An ORM here would hide exactly the SQL this project needs to be able to read.**

**3. Placeholders become `$1`, `$2`.** `pg` does not accept `?`. **A `?`→`$n` shim was considered and rejected**: it would shrink the diff and add a translation layer between the SQL you read and the SQL that runs, in a project whose whole discipline is that provenance is inspectable.

**4. JSON columns become `jsonb`.** The seeds already wrap these values in SQLite's `json()`, so the intent was always JSON — `jsonb` is that intent with enforcement. **This deletes a test rather than adding one**: `json_valid()` can no longer be violated, because the column type forbids it.

**5. Machine timestamps become `timestamptz`. Domain dates stay `text` — deliberately.**

> **This corrects something I wrote in the docs earlier today**, which said the date columns become `timestamptz` and called it a clean win. **Half of that is wrong and the half that is wrong is the important half.**
>
> `created_at`, `updated_at`, `seen_at`, `applied_at` are written by `now()`. They have no timezone ambiguity and convert for free.
>
> **`closes_at`, `qa_closes_at`, `prebid_at`, `ends_at`, `starts_at`, `posted_at`, `awarded_at` are different.** The corpus carries `MM/DD` from a manifest, with no time and no zone. Casting `'2026-08-15'` to `timestamptz` yields midnight **UTC**, which renders as *August 14, 8:00 PM* to a user in Eastern. **A deadline that displays as the previous day is a real defect**, and `closes_at` is the highest-consequence extracted field in the system (§8.4).
>
> The right model is probably `date` for contract and award dates and `timestamptz` for solicitation deadlines — **but that is a modelling decision about timezone semantics, and this is a driver swap.** Deciding it here would be exactly what §4.7.5 warns about. **Recorded as a follow-up in "What this slice does not finish."**

**6. Tests get their own Postgres schema per file, and a local Postgres to run against.** `search_path` is per-connection, so it is set once per pool via `options: '-c search_path=…'` rather than per query. Each test file creates its schema, migrates into it, and drops it. **This preserves the existing pattern** — set an env var, then dynamically import the module that reads it — so the test files change shape as little as possible.

**7. `enabled` becomes a real `boolean`, and the API response changes with it.** `{"enabled": 1}` becomes `{"enabled": true}`. **This is a visible API contract change** and the client has not shipped a consumer of it yet, which is why it is safe now and would not be later.

```ts
import pg from "pg";

/* MANAGED POSTGRES ON NEON (workflow spec §1, revised 2026-08-13).
 *
 * This file used to open one local SQLite file. It cannot: Vercel has no
 * writable persistent filesystem, so a SQLite file does not survive a
 * request there. The hosting choice decided the database.
 *
 * OPEN DECISION, do not settle it here: one database per FIRM, or one
 * shared (workflow spec §9.3). The connection string is read from the
 * environment precisely so that stays open -- per-firm means varying this
 * value, not rewriting callers. Unchanged in intent from the SQLite version.
 */

/* `pg` returns bigint as a STRING to avoid silent precision loss, which is
 * correct and useless to us: value_cents is bigint and every consumer wants
 * a number. JS integers are exact to 2^53, and a contract of nine thousand
 * trillion dollars is not a case we need. Parsed here, once, rather than at
 * fourteen call sites. */
pg.types.setTypeParser(20, (v) => (v === null ? null : Number(v)));

const CONN = process.env.DATABASE_URL;
if (!CONN) {
  throw new Error(
    "DATABASE_URL is not set. Copy .env.example to .env, or run `vercel env pull`.",
  );
}

/* Confines every connection in this pool to one schema. Used by the test
 * harness so each test file gets an isolated namespace in the same database
 * -- search_path is per CONNECTION, so it is set on the pool rather than
 * issued per query, which a pooled client would lose. */
const SCHEMA = process.env.TENDERFOOT_SCHEMA;

export const pool = new pg.Pool({
  connectionString: CONN,
  ...(SCHEMA ? { options: `-c search_path=${SCHEMA}` } : {}),
  /* Small on purpose. One user, and serverless concurrency against a
   * connection ceiling is the documented failure mode. Neon's POOLED
   * endpoint does the real multiplexing. */
  max: Number(process.env.PGPOOL_MAX ?? 5),
});

export interface Querier {
  all<T = any>(sql: string, params?: unknown[]): Promise<T[]>;
  one<T = any>(sql: string, params?: unknown[]): Promise<T | undefined>;
  run(sql: string, params?: unknown[]): Promise<number>;
  insert(sql: string, params?: unknown[]): Promise<number>;
}

function querier(exec: (sql: string, params: unknown[]) => Promise<pg.QueryResult<any>>): Querier {
  return {
    async all<T>(sql: string, params: unknown[] = []) {
      return (await exec(sql, params)).rows as T[];
    },
    async one<T>(sql: string, params: unknown[] = []) {
      return (await exec(sql, params)).rows[0] as T | undefined;
    },
    async run(sql: string, params: unknown[] = []) {
      return (await exec(sql, params)).rowCount ?? 0;
    },
    /* Replaces better-sqlite3's lastInsertRowid. The SQL must end in
     * `RETURNING id` -- asserted rather than assumed, because a silent
     * undefined here becomes a null foreign key three lines later. */
    async insert(sql: string, params: unknown[] = []) {
      const row = (await exec(sql, params)).rows[0];
      if (!row || row.id === undefined) {
        throw new Error(`insert() requires a RETURNING id clause: ${sql.slice(0, 80)}`);
      }
      return Number(row.id);
    },
  };
}

const base = querier((sql, params) => pool.query(sql, params as any[]));
export const { all, one, run, insert } = base;

/* One transaction, one client. better-sqlite3's db.transaction(fn)() was
 * synchronous and could not have been doing this wrong; a pool can, because
 * BEGIN on one client and INSERT on another is two connections and no
 * transaction. The callback receives a client-bound Querier so that mistake
 * is not available. */
export async function tx<T>(fn: (q: Querier) => Promise<T>): Promise<T> {
  const client = await pool.connect();
  try {
    await client.query("BEGIN");
    const out = await fn(querier((sql, params) => client.query(sql, params as any[])));
    await client.query("COMMIT");
    return out;
  } catch (err) {
    await client.query("ROLLBACK");
    throw err;
  } finally {
    client.release();
  }
}

export async function close(): Promise<void> {
  await pool.end();
}
```

```ts
import { readdirSync, readFileSync } from "node:fs";
import { dirname, join } from "node:path";
import { fileURLToPath, pathToFileURL } from "node:url";
import { all, run, tx } from "./index.js";

/* Hand-rolled rather than a library (SP0 plan, decision 2): ~40 lines, no
 * dependency, fully inspectable. The first migration is the project's most
 * expensive early commitment (§2.2), so the thing applying it should be
 * readable in one sitting. Unchanged reasoning; changed driver. */

const DIR = join(dirname(fileURLToPath(import.meta.url)), "../../migrations");

export async function migrate(verbose = true): Promise<string[]> {
  await run(`CREATE TABLE IF NOT EXISTS schema_migrations (
    name       text PRIMARY KEY,
    applied_at timestamptz NOT NULL DEFAULT now()
  )`);

  const applied = new Set((await all<{ name: string }>("SELECT name FROM schema_migrations")).map((r) => r.name));
  const files = readdirSync(DIR).filter((f) => f.endsWith(".sql")).sort();
  const ran: string[] = [];

  for (const file of files) {
    if (applied.has(file)) continue;
    const sql = readFileSync(join(DIR, file), "utf8");
    /* Each migration is one transaction. A half-applied migration is worse
     * than an unapplied one, because it looks like it worked.
     *
     * Postgres also makes DDL transactional, which SQLite did not fully --
     * so this guarantee got stronger rather than weaker. */
    await tx(async (q) => {
      /* Multi-statement SQL goes through the simple query protocol, which
       * requires NO parameters. Every migration file is parameterless; if
       * one ever needs a value, it splits into its own statement. */
      await q.run(sql);
      await q.run("INSERT INTO schema_migrations (name) VALUES ($1)", [file]);
    });
    ran.push(file);
    if (verbose) console.log(`applied ${file}`);
  }
  if (verbose && ran.length === 0) console.log("no pending migrations");
  return ran;
}

export async function appliedMigrations(): Promise<string[]> {
  return (await all<{ name: string }>("SELECT name FROM schema_migrations ORDER BY name")).map((r) => r.name);
}

/* Entry-point guard. `file://${process.argv[1]}` is WRONG on Windows: argv[1]
 * is a backslashed path (C:\...) while import.meta.url is a file:///C:/...
 * URL, so the comparison silently never matches and the CLI does nothing.
 * pathToFileURL normalises both sides. Found by SP0's own verification. */
if (process.argv[1] && import.meta.url === pathToFileURL(process.argv[1]).href) {
  const { close } = await import("./index.js");
  console.log(`database: ${new URL(process.env.DATABASE_URL!).host}`);
  await migrate();
  await close();
}
```

> **Note the last line changed on purpose.** It used to print `DB_PATH`. **Printing the connection string would print the password**, which is how a secret ends up in a CI log. Host only.

```ts
 *

/** Call BEFORE importing anything that opens a pool. Returns the schema name. */
export function useTestSchema(name: string): string {

    throw new Error(
      "DATABASE_URL_TEST is not set. Copy .env.example to .env and paste the Neon `test` branch string.",
    );

  process.env.TENDERFOOT_SCHEMA = name;

/** Drop and recreate the schema. Runs on its own connection, outside the pool. */
export async function resetSchema(name: string): Promise<void> {
  const admin = new pg.Client({ connectionString: process.env.DATABASE_URL_TEST });
  await admin.connect();
  try {
    await admin.query(`DROP SCHEMA IF EXISTS ${name} CASCADE`);
    await admin.query(`CREATE SCHEMA ${name}`);
  } finally {
    await admin.end();
  }
}
```

  > **`::` binds tighter than `||`.** So `json('a' || 'b' || 'c')` translated as `'a' || 'b' || 'c'::jsonb` casts **only the final fragment**, leaving the rest as text. **Parenthesise the whole concatenation before casting:** `('a' || 'b' || 'c')::jsonb`.

## What to watch

**The gate's speed.** Tests now need a running Postgres. If `npm run check` stops being a few seconds, it stops being run — an existing watch item in `Proto2PRD-Lessons.md`, now with a new way to fail.

**`upsertOrg` and the transaction.** The one place in this port where the synchronous original could not have been wrong and the async version can: a helper that quietly uses the pool instead of the transaction's client commits outside the transaction, and a rollback then leaves orphan rows with nothing reporting it. **Task 11 step 2 exists entirely because of this.**

**Silent bigint truncation.** If `value_cents` ships as `integer`, nothing fails — values above ~$21.4M just come back wrong. **No test can catch what the schema permits**, which is why Task 6 step 3 checks it with eyes rather than with an assertion.

**The `enabled` contract change.** `1` became `true`. Nothing consumes it today. After SP6 this would have been a breaking change to a working screen.
